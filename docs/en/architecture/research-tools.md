# Research tools, model provenance and charting

Canonical language: English. Revision: 2. Original assessment: 2026-10-18. Evidence recovery: 2026-10-19. Status: Phase III architecture assessment; no package installation, model execution or financial experiment is claimed by this document. [Spanish counterpart](../../es/architecture/research-tools.md). The [source register](../../architecture/research-tool-sources.jsonl) contains eight official source bundles, including retrieval failures and pinned repository revisions. These are engineering sources, not additions to the 53-study scientific corpus.

## Recommendation

Use **TradingView Lightweight Charts (LWC)** behind a replaceable chart adapter for candlesticks, volume and time-series overlays. Keep calculations, data availability rules and authoritative research results in Python/backend services. Use the project's own typed research records and artifact manifests as the primary interfaces. **Do not adopt Qlib or RD-Agent as the application framework, or require MLflow as an initial service.** Preserve explicit adapter boundaries so an optional integration can be justified later without replacing the scientific controls.

This recommendation concerns engineering fit and scope. It does not select a strategy, assert financial superiority, or authorize an autonomous search, an LLM bill or a financial experiment.

## Version and security findings that affect the design

**Qlib source versus release.** The pinned README explicitly labels artifact-loading/configuration changes as **unreleased**. It describes restricted recorder loads and a `trusted=True` opt-in for certain saved models/datasets, with migration requirements. It also reports its official dataset temporarily disabled and links community data. Do not infer that these controls already exist in an installed release, that every artifact is safe, or that linked datasets are licensed/apt for this project. Resolve and audit a specific release if integration is later approved.

**RD-Agent execution boundary.** Its current README requires authenticated UI access, advises isolated least-privileged workers and restricted egress, and says generated code must not receive host credentials or the Docker socket. These are relevant source-level statements, not a security guarantee for every version. Reading the README or reusing a workflow idea does not authorize running its quant loop, downloading demo datasets or using a provider key.

**MLflow network boundary.** Official network documentation describes DNS-rebinding, CORS and clickjacking middleware for the default FastAPI/uvicorn server in 3.5.0+, and explicitly excludes the gunicorn/waitress paths from those middleware features. Such middleware does not replace authentication, authorization, TLS or artifact-store permissions. The security landing page returned HTTP 403; its official repository documentation was read instead. No server was started. Version pins and package hashes reduce some supply-chain risks; they do not prove a dependency safe.

**Mutable references are not scientific identities.** `models:/name@champion` can change target. Model versions and registry IDs alone also do not prove immutable bytes or complete lineage. Future integrations must resolve aliases once, record the concrete version plus artifact digest and keep the project's manifest. Pin source commit, configuration, dependencies/environment, model snapshot, feature/target definitions, dataset snapshot and available-at semantics, partition/holdout reference, seeds where applicable, and all attempted variants. Unknown training cutoff or unavailable provider snapshot remains an explicit limitation.

## Research/AI boundaries and future integration contracts

The following are architectural requirements, not implemented interfaces or experiment results:

1. **Proposal:** hypothesis ID, null/comparator, mechanism, required data, authorized scope, finite variant/resource budget and rejection criteria. Preserve negative and abandoned proposals. A generated proposal needs the same review as a human proposal.
2. **Attempt:** unique run/parent IDs, status and timestamps, plan/configuration digest, code/dependency version, dataset and split IDs, artifact manifests, resource usage and failure details. Separate infrastructure checks from scientific attempts; keep failures rather than overwriting a successful run's record.
3. **Artifact reference:** typed format/schema, size, digest, provenance and access policy. A matching digest establishes identity, not trustworthiness. Prefer data-only validated formats at service boundaries. Do not deserialize arbitrary downloaded pickle/joblib/model objects or execute configuration-supplied code in the API process. Any later approved executable model requires an isolated, explicitly trusted loading path.
4. **Evaluation permissions:** a worker cannot grant itself broader data access, change the registered search budget, open the final holdout, promote a model or enable an execution capability. Logging in MLflow does not confer these permissions. The run record and authorization are distinct objects.
5. **AI-assisted review:** external reports, webpages, dataset text and model responses are untrusted content. Embedded instructions cannot authorize code execution, tool calls, uploads or budget changes. Record model/provider/snapshot or stated lack of a fixed snapshot, prompt/template version and retrieved-source IDs. Redact secrets and respect data licenses before any external transmission.
6. **Resource limits:** any future assisted runner needs explicit job/time/memory/CPU/GPU, retry, token/request and spending limits, cancellation and failed-run accounting. A zero or absent paid-service authorization means no paid calls. No self-retrying loop can turn an inconclusive result into permission to search indefinitely.

A future MLflow adapter may mirror these records without becoming the only copy of provenance. Qlib may supply a model/data adapter only after calendar, universe, costs and accounting parity are demonstrated. RD-Agent may propose structured drafts only in an approved capability scope; autonomous experimentation requires separate authorization and the later scientific protocol. No integration receives trading, deployment, publication or purchasing permissions by inheritance.

No scheduler product is selected from this review. Initially, bounded explicitly submitted jobs are sufficient for architecture design. If scheduling is later necessary, require idempotency keys, UTC due/started/completed times, retry limits, cancellation, failure visibility and one authoritative owner per job before adding a queue/service. Infrastructure must not silently schedule financial experiments.

## Chart contract and licensing requirements

The adapter accepts validated series and display metadata; it does not query an exchange directly or compute the authoritative research result. Its contract should include instrument/venue/product identifiers, base/quote/unit, USD conversion provenance where applicable, interval boundaries and timestamp convention, source snapshot, observed/available times when relevant, quality flags, and an explicit synthetic/demo label. UTC storage and display-timezone selection must preserve the underlying instant. Never relabel USDT or USDC as USD without the documented conversion.

Backend services own aggregation, feature/indicator definitions, resampling policy, gap handling and result calculations. Preserve exact accounting quantities in the backend; finite numbers converted for drawing are a display representation. Distinguish an incomplete current bar from a completed bar. Do not turn missing prices into zero or silently interpolate a tradable path. Display decimation/aggregation must be labeled and must not feed scientific calculations. The drawing adapter owns rendering, pan/zoom/crosshair, resize and disposal; it should be replaceable without changing data meaning.

Initial LWC integration can expose candlesticks and a volume histogram with clear units, plus precomputed overlays. Markers, drawings, synchronized panes, screeners, economic calendars, alerts and persistent layouts are separate application/plugin requirements. The documented extension API does not make them a complete turnkey feature set, confer data rights or guarantee correct strategy calculations. Persist any later annotations as validated data, not executable code. Contract tests should cover ordering, duplicate timestamps, missing bars, empty data, timezone/units, resource disposal and accessible textual alternatives; they test software behavior, not financial edge.

LWC's current README instructs applications to include **the attribution from NOTICE and a link to TradingView on a page available to users**. Preserve the release's exact notice in shipped third-party notices, show it in an accessible application attribution location, and retain the chart's `attributionLogo` link (or equivalent documented link). The README says the logo satisfies the link requirement; do not assume it replaces the textual notice. Keep attribution visible in both supported interface languages. Retain Apache-2.0 and bundled tslib notices. If ECharts replaces LWC, retain its own Apache NOTICE and subcomponent notices instead of reusing LWC's licensing assumptions.

## Acceptance and reconsideration

This review is complete as a bounded engineering-source assessment. It does not install, benchmark or validate the named frameworks. Reconsider a deferred integration only for a specific need: costly duplication that Qlib demonstrably removes after crypto adaptation; a multi-user tracking requirement that justifies MLflow; or an explicitly authorized, isolated and budgeted AI research use case. Require a pinned-release compatibility/security/license check and a small technical acceptance test before adoption. Preserve a simple independent baseline and the ability to export records/data without the framework.

The original assessment records eight source bundles on 2026-10-18; multiple resources within a bundle are not independent scientific evidence. Recovery on 2026-10-19 verified all 20 cached artifact hashes against their retained manifests, plus the two gzip-decoded hashes, and re-examined the cited sections. The recovered register identifies pinned repository revisions, selected README/license/documentation scope, the moved Advanced Charts page and historical failures preserved from manifests. Original receipt timestamps were absent from those manifests and are not invented; the new verification/read events carry their actual recovery date. No academic claims were newly validated and no vendor performance promise is adopted.
